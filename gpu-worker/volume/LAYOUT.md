# RunPod network volume layout

Volume name: `urdu-video-models` · Size: 50 GB · Region: **EU-RO-1**
Mount point (Serverless and Pods): `/runpod-volume`

Weights live on the volume, **never** in the Docker image (T088). The image only
contains ComfyUI + Python deps; `comfyui/extra_model_paths.yaml` points ComfyUI at
the folders below.

```
/runpod-volume/
├── models/
│   ├── wan2.2-ti2v-5b/                    # ComfyUI model root for Wan 2.2
│   │   ├── diffusion_models/
│   │   │   └── wan2.2_ti2v_5B_fp16.safetensors        (~10 GB)
│   │   ├── text_encoders/
│   │   │   └── umt5_xxl_fp8_e4m3fn_scaled.safetensors (~6.7 GB)
│   │   └── vae/
│   │       └── wan2.2_vae.safetensors                 (~1.4 GB)
│   └── omnivoice-urdu-6000/               # full HF repo snapshot (OmniVoice Urdu)
└── voices/
    ├── male.wav        # reference voice, mono, ~5-15 s clean speech
    ├── male.txt        # exact transcript of male.wav (Urdu)
    ├── female.wav
    └── female.txt
```

## Notes

- Filenames under `diffusion_models/`, `text_encoders/`, `vae/` must match the names
  hard-coded in `workflows/wan22_ti2v5b.json`.
- `voices/*.txt` are an addition to the required `.wav` files: OmniVoice's
  `generate()` takes `ref_text` (transcript of the reference clip) alongside
  `ref_audio`. If a `.txt` is missing, `omnivoice/infer.py` omits `ref_text`.
- Voice ids used by the backend (`male`, `female`) map to `voices/<id>.wav`.
- `voices/*.wav` are **not** downloaded by `download_weights.sh`. They are synthesized
  by `scripts/make_voices.py` with OmniVoice Voice Design (see below); no real person's
  voice is cloned.
- Keep the volume in EU-RO-1; Serverless endpoints must be deployed in the same
  region/data center to mount it.

## Preset voices (Voice Design)

Generated by `scripts/make_voices.py` on a GPU pod with the volume attached. Each voice
is designed from a text description (no reference speaker) reading this fixed Urdu
sentence (10 words), which is also stored in the matching `.txt`:

> آج موسم بہت خوشگوار ہے اور آسمان بالکل صاف ہے۔

OmniVoice's `instruct` accepts only a fixed tag vocabulary (gender, age, pitch, whisper;
accents are English-only, dialects Chinese-only), so free-form wishes like "warm,
teacher-like, steady pace" cannot be expressed and were translated to age/pitch tags.
Three candidates per gender are generated (`male_1..3.wav`, `female_1..3.wav`, plus
`.txt`); `male.wav`/`female.wav` start as candidate 1 until you choose with
`--pick male=N female=N`. Each candidate is also verified as a cloning reference for the
Urdu fine-tune (outputs in `voices/_verify/`).

| Candidate | Instruct prompt | Seed |
|---|---|---|
| male_1 (default; mid-30s teacher-like) | `male, middle-aged, moderate pitch` | 1001 |
| male_2 | `male, young adult, low pitch` | 1002 |
| male_3 | `male, young adult, moderate pitch` | 1003 |
| female_1 (default; late-20s narrator) | `female, young adult, moderate pitch` | 2001 |
| female_2 | `female, young adult, high pitch` | 2002 |
| female_3 | `female, middle-aged, moderate pitch` | 2003 |

**Chosen voices:** _not chosen yet_ - after listening, record the picks here, e.g.
`male = male_2 (male, young adult, low pitch)`.

Design runs on the Urdu fine-tune first and falls back to the base `k2-fsa/OmniVoice`
if `instruct` is unsupported or yields unusable audio. A fine-tune could also *silently*
ignore `instruct`; if male and female candidates sound alike, rerun with
`--design-model base`. Seeds make a run repeatable on the same hardware/software.

## Image versions (gpu-worker/Dockerfile)

Researched 2026-11-05. Fixes the startup crash `infer_schema(func): Parameter stride has
unsupported type list[int]` (comfy_kitchen on torch 2.5.1).

| Component | Pin | Why |
|---|---|---|
| Base image | `pytorch/pytorch:2.14.1-cuda13.0-cudnn9-runtime` (~3.3 GB) | ComfyUI needs torch >= 2.7 (minimum) and recommends recent torch + cu130; runtime variant keeps the image lean |
| CUDA | 13.0 | Runs on hosts with driver CUDA >= 13.0, incl. the RunPod host reporting 13.2; matches ComfyUI's cu130 wheels |
| ComfyUI | `v0.44.0` (`COMFYUI_REF` build arg) | Tag, not master. Contains `Wan22ImageToVideoLatent`, `CreateVideo`, `SaveVideo` |
| comfy-kitchen | 0.2.40 (pinned by ComfyUI v0.44.0 requirements) | |
| torch / torchvision / torchaudio | 2.14.1 / 0.29.1 / 2.11.0 (all `+cu130`, as shipped in the base image), held by `gpu-worker/constraints.txt` | Prevents pip from pulling a second torch (container disk ~5 GB). Verified: versions unchanged after the build |
| Python / pip | system Python 3.12 (PEP 668 managed) + `ENV PIP_BREAK_SYSTEM_PACKAGES=1 PIP_NO_CACHE_DIR=1` | The base image refuses plain `pip install`; the env var covers every pip step |

`workflows/wan22_ti2v5b.json`: all node class names (`UNETLoader`,
`CLIPLoader`, `VAELoader`, `ModelSamplingSD3`, `CLIPTextEncode`, `Wan22ImageToVideoLatent`,
`KSampler`, `VAEDecode`, `CreateVideo`, `SaveVideo`) were checked against v0.44.0. One input change: `SaveVideo` no longer gets a flat `"codec":"h264"` (v0.44.0 made codec a nested dynamic combo); `format: mp4` with the default auto codec produces H.264.
To upgrade: change `COMFYUI_REF`, re-check the nodes and torch minimum in that tag's README.

Verified locally (`docker build -f gpu-worker/Dockerfile .`): build succeeds; `import comfy_kitchen`
works on torch 2.14.1; `python main.py --cpu --quick-test-for-ci` exits 0; `import omnivoice` works.
Not verifiable without a GPU: actual CUDA init and a real generation job on RunPod.
Image size on disk: base 6.3 GB, final ~9.0 GB (+2.7 GB). pip resolves `gradio` to the old 3.36.1
via omnivoice's unpinned dependency (`import omnivoice` still works; not checked whether inference touches gradio).
